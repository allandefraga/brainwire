# Mixed load and restart: v0.17 candidate

Two short, synthetic runs exercised a standalone database in a 2 GiB Docker
container with two CPUs. Each loaded 10,000 nodes and 10,000 relationships,
then ran one writer and one reader concurrently for 120 seconds. The writer
repeated updates in batches of 250. Each full minute had successful writes and
reads. After acknowledged writes stopped, the runner checked all pairs, killed
the process, restarted it with the same volume and checked all pairs again.
Both runs passed and reported no cgroup OOM.

| Image | Committed batches | Successful reads | Highest sampled process RSS |
| --- | ---: | ---: | ---: |
| v0.17.0-beta.1 published image | 1,916 | 2,093 | 135,303,168 bytes |
| v0.17.0-beta.2 local candidate | 2,457 | 2,532 | 143,192,064 bytes |

The [baseline receipt](../../benchmarks/results/2026-11-07-beta1-mixed.json)
and [candidate receipt](../../benchmarks/results/2026-11-07-beta2-mixed.json)
record image identities, timings, progress and memory samples. The candidate
image was locally built from the release source; it is not the published image.

These are single runs on a shared host with other work in progress. Sampled RSS
can miss peaks, and a 2 GiB limit is not an RSS guarantee. The workload does
not isolate the Cypher functions changed in this version, so differences in
counts cannot be attributed to that optimization. This is neither a production
capacity test nor a test of power loss, ambiguous commits, disk loss or
multi-machine failover.

To repeat the experiment with a local candidate image and the Bolt driver
installed:

```sh
python scripts/bench_mixed_recovery.py --image YOUR_IMAGE --rows 10000 \
  --batch 250 --seconds 120 --deadline 600 --memory 2 --sample-seconds 5 \
  --pause 0.02 --output /tmp/mixed-receipt.json
```

The runner owns and removes its synthetic Docker container and volume. Do not
point experiments at production data.
