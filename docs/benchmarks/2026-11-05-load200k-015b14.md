# Synthetic 200,000-node diagnostic: v0.15.0-beta.14

A local, disposable integration test passed with 20 labels and 10,000 nodes
per label. The initial load used Cypher `CREATE`: 200,000 nodes and 200,040
relationships. A Python/Bolt application writer then updated 20,000 nodes,
inserted 2,000 nodes, replayed the batch, updated 2,000 relationships, removed
2,000 properties and deleted 2,000 relationships and 2,000 nodes. A duplicate
`CREATE` was rejected and its transaction rolled back.

After an abrupt restart, counts remained 200,000 nodes and 196,040
relationships; the offline storage audit passed. [Results and memory
samples](2026-11-05-load200k-015b14.json) identify the local container image.
The fixture and application writer are external to the repository, so this is
an integration receipt, not a standalone reproducible benchmark.

The container had a 2 GiB limit and two CPUs on a shared host. Observed peak
process RSS was about 187.9 MiB; the cgroup peak was about 240.4 MiB, with no
observed OOM events. The external samples were sequential, and observers also
used cgroup memory. The synthetic properties were highly compressible. These
numbers are neither sizing advice nor a hard RSS ceiling, and this short test
does not qualify sustained workloads or distributed operation.
