# Keyed relationships on one endpoint pair

This local diagnostic repeatedly writes 10,000 synthetic events between the
same two nodes. The separate containers used two CPUs, a 2 GiB memory limit,
100-row batches and 256-byte payloads on a shared host. Times include the Bolt
client and transaction commits. Each number is one run, not a production SLO.

| Phase | beta.2, index ready | beta.3 candidate, index ready | beta.3 candidate, no index |
| --- | ---: | ---: | ---: |
| Insert first 5,000 | 3.59 s | 0.26 s | 2.75 s |
| Replay first 5,000 | 7.32 s | 0.22 s | 3.92 s |
| Append 5,000 | 10.82 s | 0.17 s | 6.20 s |
| Replay all 10,000 | 32.28 s | 0.36 s | 15.57 s |

The property index was explicitly enabled and ready before the indexed runs;
its setup time is recorded separately. The faster path depends on an eligible
standalone index on a merge key. Without one the candidate still scans the
endpoint pair, but decodes less data and accounts for temporary memory by peak.
Each run checked event contents, replay, abrupt restart and offline integrity.
Results do not establish throughput under concurrency, large ontologies,
network latency, replicated deployments or production workloads.

A second comparison declared 100 additional empty node labels, without adding
their records or relationships. With an index ready, replay of all 10,000
events took 29.62 s in beta.2 and 0.76 s in the final beta.3 candidate. This
checks one larger catalog shape; empty labels do not represent a realistic
wide production ontology. [Previous receipt](2026-11-07-keyed-wide-beta2.json) ·
