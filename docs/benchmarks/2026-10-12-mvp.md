# October 12 MVP qualification

This session adds a source-export path, connected operational panes, Cypher
string functions and Bolt admission protections. It qualifies a protected
single-node synthetic shadow workflow, not production external application data or replicated
operation. See the [runnable quickstart](../mvp-quickstart.md) and
[beta operator checklist](../beta-operator-checklist.md).

## Implemented behavior

- DuckDB SELECT export writes bounded normalized JSONL through a private temporary
  file, commits source reads, then exclusively publishes the final immutable file.
  Active caller transactions and existing destinations are refused. Nulls/lists,
  shared mapping validation, ticket-before-comment ordering and SHA-256 receipts
  feed the existing durable Python import cursor.
- Local SQLite DuckLake export attaches read-only at an explicit snapshot version.
  Catalog/data paths must exist; cached extensions must already be installed.
  Implicit extension installation and managed-path overrides are disabled.
- Connected Memory and Indexes use authenticated, bounded Bolt snapshots. Memory
  explains shared query reservations, including its sampling query; it requires
  instance administration. Ordinary graph readers can inspect index declarations.
  EN/PT panes support manual refresh, sample age and stale/recovered state; Indexes
  additionally supports selection and scrolling.
- Cypher `toLower`/`toUpper` support strings, null propagation and whole-string
  Unicode conversion. Wrong types/arity fail; indexed SET preserves old/new index
  consistency and rollback. Conversion reserves a conservative 24 times input
  bytes plus value overhead before allocation.
- Bolt caps assembled payload per request, independent of TCP coalescing. It
  rejects announced oversized chunks before reading bodies and rejects trailing
  PackStream bytes. Negotiation and authentication each have a separate ten-second
  absolute IO budget; LOGOFF starts another authentication budget.
  A read cursor compacts consumed framing bytes once per incoming read, removing
  repeated buffer shifts for NOOPs and coalesced messages. Structural regressions
  verify this behavior; no timing speedup is claimed.

The protected bridge tests exact committed counts, final cursor consistency and
no-write completed replay. Its SIGKILL occurs after a completed import; it does
not itself prove mid-import crash atomicity. The separate recovery harness tests
pending data/cursor rollback and lost receipts.

Import rates count source rows, not graph mutations: one comment also creates an
edge. The workstation ran other tests/builds concurrently; these observations are
not controlled comparative benchmarks, production throughput promises or SLOs.
The different hashes and host contention preclude an inferred speedup.
RSS is sampled approximately every five seconds; peaks between samples may be
missed. The writer is deliberately throttled, so this is not write-saturation
throughput. Both load receipts verify latest values after crash, not historical
versions. The 30-minute and 10-minute runs are separate qualification periods;
they cannot be summed into the one-hour continuous endurance gate.

## Reproduce

Build the release CLI first. Run from the repository root with cached optional
Python packages/extensions:

```sh
cargo build --release --locked --offline -p brainwire-server
uv run --no-project --with duckdb==1.5.5 --with neo4j==6.3.0 python docs/benchmarks/2026-10-12-mvp/acceptance.py --tickets 100000 --ducklake
python3 docs/benchmarks/2026-10-12-mvp/transport.py
uv run --no-project --with neo4j==6.3.0 python docs/benchmarks/2026-10-12-auth/acceptance.py
docker build -t brainwire:mvp-20261012 .
uv run --no-project --with neo4j==6.3.0 python crates/server/tests/compose_auth.py --image brainwire:mvp-20261012
```

The bridge uses an 8 MiB request cap and 64 MiB query/cache budgets with 16 MiB
memtables. The Docker acceptance uses its recorded Compose profile. They do not
establish interchangeable RSS limits. Source extension version `d8a1881e` is a
DuckLake build identifier under DuckDB 1.5.5, not a semantic version guarantee.

## Remaining qualification

Actual external application mappings, catalog/backend access, payloads and query SLOs still
need approval and real-source qualification. PostgreSQL catalogs, object storage,
CDC, deletions and source history retention are not provided by this snapshot
exporter. DuckLake must retain the managed files referenced by the pinned version.
The lexical DATA_PATH must match the catalog's stored spelling; a resolved symlink
or another spelling is not silently accepted.

Source final publication does not fsync the directory: there is no claim of
power-loss durability for its filename. An uncatchable exporter death can leave a
private temporary file. Arbitrary SELECT SQL is trusted, not sandboxed; a DuckDB
transaction does not pin mutable external Parquet files.

The server still materializes results. Request payload caps do not account for
all decoded PackStream allocations, which precede query-pool accounting.
Connected-client byte/row caps do not
bound server materialization. TUI refresh is synchronous and can block input up
to its request deadline. Query-pool accounting is neither process RSS nor cache
telemetry. Unicode allocation accounting can conservatively reject long strings.
Authentication IO deadlines do not cancel blocking engine work or impose a hard
connection lifetime. Established-session idle limits, responsive cancellation,
native drain, TLS, replicated failover and executed Kubernetes/Swarm target
qualification remain open. A 30-minute soak is not the required one-hour
continuous beta endurance gate.
