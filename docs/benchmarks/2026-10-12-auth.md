# October 12: protected Cypher, connections and container acceptance

This session adds optional service-token authentication, exact named-graph
read/write grants and separate process-telemetry permission. Cypher checks the
whole statement before execution. Python and native connected ontology/probes
share a strict credentials-file format. `coalesce(...)` now supports lazy defaults.

The [connection guide](../bolt-auth.md) and [container guide](../protected-containers.md)
are the operational entry points. All work and artifacts stayed local.

The driver harness covers malformed policy before bind, wrong/missing tokens,
explicit/default graph grants, mutation denial, process telemetry permission,
atomic multi-RUN overwrite/rollback, lazy defaults and the authenticated public
snapshot CLI plus module/direct-script Customer import/resume entry points. Reader credentials also execute sparse projection, degree, PageRank,
reachability, shortest path and explainable knowledge ranking with known answers.
Native probe and real connected ontology fetch use the same credential path.
Restart revocation and offline graph/index audit passed.

New real-store session tests additionally cover LOGOFF before PULL in implicit
and explicit transactions, relogin as a different reader, RESET after logout and
invalid/repeated LOGON during streaming. Pending writes/results are discarded and
shared query reservations return to zero. These tests exercise the production
DbEngine bridge, in addition to Bolt state-machine tests.

The Compose harness owns a fresh UUID project and temporary volume, tests only
synthetic credentials and removes its resources afterward. A protected explicit
transaction remains open during SIGKILL: its pending node and indexed email
change are absent after recreation, while the old value/index and 1,000 committed
records survive. The image also executes `coalesce` defaults correctly. Swarm and Kubernetes
were **rendered only**, not run in a target cluster during this session. Older
unprotected cluster receipts do not certify these new protected profiles.

## Mixed-load observation

Release binary on localhost, macOS 26.6.2, Apple M5/32GiB; Neo4j Python driver
6.3.0. Configured cache 64MiB, memtables 16MiB, shared query pool 64MiB. The source
contains 100,000 Customer records with distinct deterministic 1,024-character
ASCII payloads in `tags`; total JSONL source is 115,277,780 bytes. The bounded
existing importer writes through protected Bolt/Cypher and ready scalar indexes.

Initial import took **3.846s**, about **26,003 input records/s**, including Python
conversion and Bolt. This is one local run, not sustained ingestion capacity.

| Operation | Requests over 900.003s | p50 | p95 | p99 |
| --- | ---: | ---: | ---: | ---: |
| Entity identity lookup | 2,301,745 | 0.588ms | 1.680ms | 4.219ms |
| Scalar email equality lookup | 2,301,743 | 0.597ms | 1.708ms | 4.265ms |
| Existing-node email update | 16,449 | 0.901ms | 5.272ms | 11.678ms |

Latencies measure complete materialized Python/Bolt requests, using a histogram
rounded upward to one microsecond. Percentiles cover all requests in the window.
Four readers alternate lookup types and return only entity ID/email. A writer
updates rotating IDs 0–199, waiting 50ms after each acknowledged request; this
limits attempted throughput to about 20 writes/s. Readers select IDs >=200.
Thus this observes concurrent clients and index maintenance, **not same-record
contention**, bulk overwrite saturation or 1KiB result streaming.

RSS sampled approximately every five seconds peaked at **93,952KiB (91.75MiB)**.
This is the largest of 180 observations, not exact peak RSS or a hard memory cap.
Observed query-pool peak was 6,069,335 bytes with zero pool rejections. The desktop
host was not isolated; Docker build/container checks overlapped part of the run.
Queries run after import and repeatedly revisit records; OS page-cache state is
uncontrolled. This is a predominantly warm workload, not cold-storage latency.
This is not the proposed fixed-resource production benchmark or an improvement
ratio against a before-change baseline.

After the workers finished, the harness killed the server with SIGKILL and
reopened the same store. It verified all 100K nodes and the latest acknowledged
updates/index entries for 200 hot nodes, then passed offline integrity audit.
Crash occurs **after** traffic, not at an arbitrary acknowledgement boundary.
Native/Compose correctness checks cover additional rollback cases separately.

## Additional hot-record overlap observation

A separate 600.005-second run uses `--hot-reads` against a freshly imported
100K-node store with the same binary, limits and source shape. Point reads select
the writer's 200 hot IDs; scalar email reads still select the other records.
The single writer keeps its 50ms wait after each acknowledged update.

| Operation | Requests | p50 | p95 | p99 |
| --- | ---: | ---: | ---: | ---: |
| Hot identity lookup | 1,874,666 | 0.534ms | 1.225ms | 2.061ms |
| Disjoint scalar email lookup | 1,874,664 | 0.551ms | 1.260ms | 2.143ms |
| Hot email update | 11,080 | 0.738ms | 2.043ms | 6.297ms |

No request errors or sampled pool rejections occurred. Sampled RSS peaked at
103,616KiB (101.1875MiB). After traffic, SIGKILL/reopen preserved all nodes and
latest acknowledged updates/index entries for 200 hot records; offline audit
passed. [Raw result](2026-10-12-auth/mixed-hot-100000-600s.json).

Concurrent point reads accept any internally consistent original/updated email
for that entity. This does not prove latest-value reads, linearizability,
monotonic reads or contention between writers. The different workload and host
conditions also do not establish a performance improvement over the first run.
Neither run measures PageRank performance, result streaming of full payloads,
replication or production data. The observed import timing is not used as a
capacity promise.

## Reproduce

From the repository root with an already built release binary:

```sh
uv run --no-project --with neo4j==6.3.0 python docs/benchmarks/2026-10-12-auth/acceptance.py
uv run --no-project --with neo4j==5.28.6 python docs/benchmarks/2026-10-12-auth/acceptance.py
uv run --no-project --with neo4j==6.3.0 python docs/benchmarks/2026-10-12-auth/mixed_load.py --rows 100000 --seconds 900
uv run --no-project --with neo4j==6.3.0 python docs/benchmarks/2026-10-12-auth/mixed_load.py --rows 100000 --seconds 600 --hot-reads
python3 deploy/check_auth_profiles.py
uv run --no-project --with neo4j==6.3.0 python crates/server/tests/compose_auth.py --image brainwire:auth-20261012
```

Harnesses generate only synthetic data and credentials, select unused loopback
ports and remove owned temporary stores/processes. The Compose command requires
the local image; it does not build or publish one. Source hashes, binary hash,
image identity and exact check counts are recorded in the validation receipt.

## Remaining boundaries

Native TLS, online policy reload, per-record ACLs, machine-loss recovery and
replicated quorum writes are not implemented by this change. Secret mounts and
orchestrator scheduling do not provide application encryption/replication. Policy
rotation requires a restart. Actual protected Swarm/Kubernetes runtime, chosen
encrypted transport, real external application mapping/data shape, longer endurance and
recovery at the supported resource profile remain release work.
