# Local Raft peer transport diagnostic — 2026-11-04

This is a small engineering diagnostic, not a distributed benchmark or a
production latency guarantee. A Linux arm64 Docker builder ran the unchanged
`pooled_peer_connections_serve_quorum_reads_and_writes` test in release mode.
The test sends 300 synthetic operations through three local Raft peers, with
the same configuration and assertions in both builds. Runs were sequential on
the same host, using the same Dockerfile and cached dependencies.

| Candidate | First run | Second run |
| --- | ---: | ---: |
| beta.6 (`4d084bd`), accepted sockets without `TCP_NODELAY` | 26.88 s | 27.01 s |
| beta.7 candidate, accepted sockets with `TCP_NODELAY` | 1.00 s | 0.76 s |

The displayed times are the test harness durations after compilation. Both
runs passed in this local environment; the separate GitHub runner recorded a
quorum refusal on beta.6. These results support a local transport latency
improvement but do not prove the cause of that particular refusal, cover real
network partitions across machines, or compare different databases.

To run the test in a Rust/Linux environment with the repository's native
dependencies installed:

```sh
cargo test --release --locked -p brainwire-replication --test network \
  pooled_peer_connections_serve_quorum_reads_and_writes -- --exact --nocapture
```

Repeat on the same machine and record load, network, durability and build
settings before comparing results.
